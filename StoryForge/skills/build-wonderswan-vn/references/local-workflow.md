The runner loads `Contents/Frameworks/libSwanAresEngine.dylib` through its C
ABI, so it tests the installed app's engine without rebuilding or mutating the
SwanSong source checkout. It preflights session creation before quarantining
old route captures, negotiates a bounded set of ABI versions around the
repository's current version, and records the selected ABI plus every attempt.
Set `SWANSONG_ENGINE_ABI=<n>` only when debugging an exact version. If session
startup fails, the command must overwrite any prior green playthrough report
with an explicit harness-failure report; stale success is never acceptable.

The polished runtime exposes a read-only `WVNDBG1`
mailbox in internal RAM with its phase, node, runtime frame, raw/new key masks,
text block, choice selection, accepted-action count, transition count, player
settings, read state, and investigation cursor.
Input pulses remain asserted for three presented frames and released for three:
SwanSong can emit a video frame before the emulated CPU reaches its next keypad
read, so one-frame synthetic taps are not reliable. The runner derives
exhaustive routes from project flags, conditional choices, branches, and
investigations; it does not reuse one choice index at every menu. The report
must prove every confirm was accepted, observed node sequences match the graph,
native audio is healthy, save-state replay is exact, and in-game save/settings
survive an engine restart and can progress after load. It writes
`reports/swansong-playthrough-report.json`, route ending PNGs, and short native
audio WAVs under `assets/swansong-playthrough/`; package them by hash. Routes
may legitimately converge on one ending scene. This is emulator evidence only,
so physical hardware status remains `pending`.

The converter may reorder nodes with a stable topological sort so explicit
jumps remain forward. `WVNDBG1` therefore reports compiled node indices, not
raw JSON list positions. The SwanSong runner mirrors that exact ordering before
mapping an index back to an ID; guard it with
`scripts/selftest_wscvn_swansong_node_order.py`. Readiness also rejects two
distinct final scene nodes that share the same terminal page and visible state.
Long-form builders must put the branch-specific ending payoff last rather than
ending every branch on one shared cadence paragraph.

Before exhaustive route enumeration, the runner uses the real in-game Options
UI once to create a hash-recorded cartridge-RAM seed with Text Speed set to
Instant. Each route stages that seed so finished scripts do not spend most of
the test budget typing characters; node logic, transitions, input, audio,
captures, and save-state behavior remain live compiled-ROM behavior. The
separate persistence test still starts from factory defaults, changes every
setting through the UI, reloads the save in a new engine, and presses through
every `{pause}` page until it proves progress beyond the loaded node.
The runner prints and flushes each `route-N (current/total)` boundary and stores
that route's `wall_time_seconds` in the report. Use those timings to distinguish
a legitimately large route matrix from one abnormally slow route; do not treat
an otherwise silent multi-route subprocess as sufficient debugging feedback.
Any parent doctor must enumerate the same route graph before launch and scale
its whole-game timeout from that route count, within bounded minimum and maximum
values. This aggregate limit complements the per-route stall watchdog; it must
not kill twenty-seven healthy routes at a four-route deadline.
On a complete `--route all` run, the runner moves only prior
`route-N-{ending,audio,stall}` evidence files into a timestamped
`reports/runtime-stale/` quarantine before capture, then records the moved
names and quarantine path. This prevents an old 27-route build from leaving
apparently current captures after a rewrite reduces the graph to nine routes,
without using destructive cleanup. Guard the behavior with
`scripts/selftest_wscvn_swansong_stale_evidence.py`.

The route runner also fails after 900 presented frames without a phase, node,
text-block, choice, transition, or accepted-action change. A stalled run records
the last `WVNDBG1` state, pending input information, host/runtime frame numbers,
and a native `route-N-stall.png` capture in the playthrough asset directory.
Use `--stall-frames` only to tune a deliberately slow project; do not disable
the watchdog to make a stuck route appear healthy.

The current runtime font came unchanged from maskofsin's upstream
`runtime/src/font.h`. It is a fixed 1bpp 8x8 table for ASCII slots 32-127. The
header calls the data public domain and says only that it was "derived from a
minimal bitmap font"; the repository does not identify a named typeface or a
more specific source. The upstream, lab, and `swanlight-ledger` copies had
SHA-256 `a097f12dc046bcf4de3ec96b2c9b502eea287e2e9fa9c81bd953d2efce18eade`

## Mandatory ImageGen Art Workflow

For every new or replacement production pictorial asset, use the built-in
ImageGen tool to create source art that already respects handheld pixel-art
constraints, then process it deterministically into WSC-safe assets. Scripted
pixel drawing, procedural geometry, and code-painted scene art are not
acceptable substitutes for ImageGen.

Save the selected ImageGen output under the game's versioned `assets/sources/`
tree before running conversion. Record the final prompt, tool, source path, and
SHA-256 in provenance or the game's QA evidence. Code may remove a chroma key,
crop, resize, quantize, snap RGB444 channels, assemble deterministic layouts,
add exact lettering/UI, derive mouth/eye variants, and render proof sheets. If
ImageGen cannot be used, stop the art pass and report that blocker.

Progress beats toolchain perfection. Once a build path is known-good, spend the
next cycle on better source art, auditions, contact sheets, and emulator review
instead of broad infrastructure work.

Use this approach for characters:

- Generate one strong master per character pose on transparency or a safe flat
  key color; do not ask imagegen to redraw talk and blink frames.
- Require a clear silhouette, stable scale and lighting, and no labels or panel
  borders.
- Prompt for large readable clusters, crisp pixel edges, limited-palette feel,
  and dark colored outlines instead of pure black.
- Locally chroma-key, crop, resize to `96x128`, and quantize the neutral master
  once to 13-15 visible colors, then derive talk/blink locally. Alternate poses
  need pose-specific mouth/eye geometry and the same x/y offset in both sprite
  audition and production conversion.

Use this approach for backgrounds:

- Generate landscape scene art with no characters, text, UI, logos, or speech.
- Ask for visual-novel composition: clear focal prop, strong planes, uncluttered
  character area, and a calmer lower area for the textbox overlay.
- Fit/crop to `224x144`, leave the opaque textbox treatment to the runtime,
  quantize to 16 colors without dithering, and validate exact dimensions.

Use this extra polish pass for WonderSwan Color assets:

- Treat the target as `224x144`, 12-bit RGB, tile-based handheld art; snap final
  channels to 17-step RGB values after quantizing.
- Compose for the official hardware envelope: two 32x32 tile screens, 8x8
  tiles, WSC 4bpp transparency where color zero is transparent, up to 128
  sprites total, and 32 sprites per scanline. Keep source details big enough to
  survive tile conversion.
- Keep character sprites to 15 visible colors plus transparency.
- Prefer versioned source art filenames such as `*_v2.png` when improving a
  project so older generated images remain available as fallback/reference.
- Build an unclipped contact sheet after every asset pass, inspect it before
  compiling the ROM, and keep the readiness report hash-bound to the current
  PNG so stale review sheets cannot pass fast status.
- Check talk/blink changes in the face band, not just globally; a mouth frame
  that only changes collar or hair pixels is not a useful VN acting frame.
- Keep `char2Id`/`char3Id` as hidden hardware animation alternates when using
  `blink`, `talking`, or `talk-blink`; do not use those fields as visible
  second-character slots in animated scenes.
- Favor cinematic inserts with one readable focal point above the textbox, a
  quiet portrait lane when a character is present, and matching
  outline/lighting language across the cast.
- Inspect `font-proof-sheet.png` and `text-preview-sheet.png` alongside the
  sprite sheets. If the font, choices, or speaker tags feel crowded at 224x144,
  rewrite the copy or improve the font before adding more scenes.
- Keep the baseline font workflow boring and proven: fixed 8x8 glyphs, stable
  glyph IDs, typed control tags, overflow checks, and preview sheets. Borrow
  fan-translation discipline without pausing progress to build a full script
  extraction/compression pipeline.

Avoid high-resolution anime portraits that are merely downscaled after the
fact. They usually lose facial readability and produce noisy palettes. The
best results come from prompts that describe the final low-resolution use.
